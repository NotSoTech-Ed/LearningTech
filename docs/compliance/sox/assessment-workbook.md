# SOX ITGC Assessment Workbook

Expand each control family into the organisation's exact risk-control matrix. Tie every row to a financial reporting process, assertion, application, owner, frequency, and evidence.

| Control family | Assessment procedure | Evidence request | Challenge prompts |
|---|---|---|---|
| Access provisioning | Select new access across material financial applications; verify approved request, role appropriateness, timely provisioning, and reviewer evidence. | Access requests; role matrix; identity logs; HR population; provisioning tickets. | Was access approved before provisioning? Does the role conflict with preparation or approval of entries? |
| Access modification and termination | Sample movers and leavers; compare HR dates to system removal/change; inspect exceptions and delayed action. | HR-to-IAM population; termination logs; mover tickets; exception approvals. | How are contractors and dormant accounts handled? Who monitors failed deprovisioning? |
| Privileged access | Review privileged population, approvals, PAM sessions, emergency access, and periodic recertification. | Admin listing; PAM reports; approvals; session logs; review attestations. | Are break-glass accounts monitored? Can administrators alter financial data and evidence? |
| Periodic access review | Reperform reviewer selection and inspect evidence, challenge, remediation, and completion. | Review population; sign-offs; exceptions; removal tickets; completion dashboard. | Is the reviewer sufficiently independent and knowledgeable? |
| Change request and approval | Sample normal changes; trace request, risk, testing, approval, segregation, migration, and post-implementation review. | Change tickets; test results; approvals; deployment logs; code repository records. | Can developers deploy to production? How are changes to report logic controlled? |
| Emergency change | Sample emergency changes; verify business justification, approval, testing, review, and later normalisation. | Emergency tickets; incident records; approval; post-implementation review. | Is “urgent” being used to bypass segregation? |
| Batch and job operations | Inspect scheduled jobs, failed-job handling, reconciliations, reruns, and evidence of review. | Schedules; run logs; failure tickets; reconciliation; operator review. | How is a missed or duplicate batch detected before posting? |
| Backup and recovery | Test backup completeness, protection, retention, restore, and recovery for financial systems. | Backup reports; restore test; DR exercise; recovery objectives; exceptions. | Does recovery preserve transaction integrity and interfaces? |
| Incident management | Sample incidents affecting financial systems; verify classification, escalation, root cause, and financial impact assessment. | Incident tickets; post-incident review; communications; problem records. | How does a technology incident reach controllership? |
| Interface and reconciliation | Test inbound/outbound interfaces, completeness checks, error handling, reconciliation, and approval of adjustments. | Interface logs; control reports; reconciliation; exception tickets; adjustment approval. | Can records be dropped, duplicated, or manually altered without detection? |
| Report and spreadsheet controls | Inventory key reports/EUCs; test parameters, logic, access, versioning, input completeness, and review. | Report catalogue; queries; spreadsheet inventory; formula protection; review sign-offs. | Who can change formulas or source data? Is the report reproducible? |
| Service organisation reliance | Assess SOC 1 scope, period, opinion, exceptions, complementary controls, bridge coverage, and gaps. | SOC 1 report; bridge letter; contract; CUEC evidence; provider issue tracker. | Does the report cover the exact service and period relied on? |
| System development and release | Test material releases and new systems for requirements, testing, approval, segregation, and production deployment. | SDLC records; test evidence; release approval; repository permissions; deployment logs. | Are accounting logic and report changes subject to finance validation? |
